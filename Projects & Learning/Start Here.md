## How tasks stay connected

Each active project, homelab task, or learning topic has its own folder, an overview, and a **Tasks.md** note. Add actionable checkboxes to that Tasks note. Big Tasks embeds the same note, so additions and completion changes appear there without copying the checklist. If supporting notes introduce an action, put the action in that folder's Tasks note and link its context.

The overview explains the goal, context, decisions, sources, and related work. Add extra notes inside its folder only when there is useful detail to keep separately. A new top-level outcome also gets a section in Big Tasks and a link from its area index.

These are [native Obsidian embeds](https://help.obsidian.md/embeds); use Reading view or Live Preview to see the checklists inline. GitHub shows the embed notation instead. No extra plugin or vault configuration change is needed.

## Rules for future brain dumps

- Update relevant overviews, Tasks notes, the area indexes, and Big Tasks when needed.
- Link shared dependencies instead of duplicating them: development VM setup belongs to HomeLab; a project's environment work links to it.
- Preserve existing task completion and decisions; distinguish user statements, old source notes, and unverified hypotheses.
- Keep unresolved details in Inbox and the relevant project note. Do not invent priorities, dates, or configuration choices.
- Projects & Learning is self-contained. Every vault link and embed must point inside this folder. When information from elsewhere is useful, bring the needed text or complete document into the appropriate folder and link to that internal copy. Assume other vault folders may disappear.
- Keep older material clearly marked when it is unverified. The existing VM name llm-gpu and GPU inventory are hardware/workload facts, not a requirement to host models.
